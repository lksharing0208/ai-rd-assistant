# Code Implementation

## 前置检查
1. 读取项目规范、相关源码、调用方和被调用方。
2. 检查工作区和已有未提交修改（工具可用时）。
3. 确认修改范围、验收标准、数据结构和测试入口。

## 实施步骤
1. 将需求映射到具体模块、文件、类和方法。
2. 采用项目已有的架构、命名、依赖和异常模式。
3. 先完成最小必要修改，不进行无关重构。
4. 保持业务语义，补齐边界、异常、权限和日志处理。
5. 为新增逻辑补充或更新测试。
6. 查看最终 Diff，确认没有意外修改。

## 质量要求
- 不随意新增框架、依赖或抽象层。
- 不吞异常，不记录凭证或不必要的个人信息。
- 项目要求中文注释时，使用中文注释。
- 未实际构建或测试，不得宣称验证通过。

## 输出
实现摘要、修改文件、关键决策、验证结果、风险和未完成项。
