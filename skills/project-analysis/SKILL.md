# Project Analysis

## 目标
用最少必要读取建立可靠项目上下文，避免脱离现有实现做设计和修改。

## 渐进读取
1. 先读 README、AGENTS.md、CLAUDE.md 和贡献规范。
2. 查看构建文件、依赖、目录和启动入口。
3. 定位任务涉及的 Controller/API、Service、Domain、Repository/Mapper。
4. 按需读取 DDL、配置、SQL、缓存、消息和测试。
5. 追踪调用方与被调用方，只扩展到关键行为可确认。

## 分析内容
- 技术栈、模块边界和构建方式。
- 入口、参数校验、业务层、数据访问和外部依赖。
- 异常、事务、权限、日志、缓存和异步行为。
- 命名、分层、DTO/Entity/VO、异常、日志、事务和测试规范。

## 输出
技术栈与模块摘要、关键入口和调用链、相关文件/符号、已确认项目规范、风险和未知项。

## 低 Token 规则
- 不遍历无关目录，不复制完整仓库内容。
- 优先返回路径、符号、行号和短摘要。
- 同一任务复用已确认事实；仅在文件变化或证据不足时重读。
- 不根据目录名称臆造实现细节。
