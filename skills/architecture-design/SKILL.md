# Architecture Design

## 执行步骤
1. 确认目标、现状、规模、约束和质量属性。
2. 识别模块边界、外部系统、数据所有权和依赖方向。
3. 优先评估沿用现有技术栈的最小可行方案。
4. 定义组件职责、关键接口、数据流和调用关系。
5. 明确事务、一致性、幂等、重试、超时、缓存和补偿策略。
6. 评估安全、权限、审计、可观测性、性能和可用性。
7. 给出迁移、兼容、回滚和分阶段实施路径。

## 输出
背景与目标、现状问题（基于已读取材料）、目标架构与职责边界、关键流程和数据流、技术决策及取舍、风险、安全和运维设计、迁移及验收。

## 规则
- 现状事实与目标设计分开描述。
- 不为抽象而增加不必要组件。
- 未经要求不引入新框架或依赖。
- 方案必须能映射到真实项目模块。
