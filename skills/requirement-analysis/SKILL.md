# Requirement Analysis

## 目标
将自然语言需求整理为边界明确、可设计、可实现、可测试的规格。

## 执行步骤
1. 提取业务目标、使用角色、触发条件、前置条件和预期结果。
2. 区分功能需求、非功能要求、业务规则和技术约束。
3. 拆分正常流程、异常流程、边界条件和状态变化。
4. 识别权限、数据归属、幂等、并发、审计及兼容性要求。
5. 明确输入输出、字段含义、默认值和校验规则；未知项标记为待确认。
6. 为关键需求定义可验证验收标准。
7. 标注影响模块、依赖系统、API、数据库、测试和文档。
8. 标注假设、风险和范围外事项。

## 输出
背景与目标、角色与场景、功能需求与业务规则、正常/异常/边界流程、非功能要求、验收标准、影响范围、假设和风险。

## 规则
- 以用户材料为准，不擅自改变业务口径。
- 区分事实、推断、建议和待确认事项。
- 能安全推进时采用明确假设，不反复追问。
- 涉及数据、安全、权限或兼容性歧义时必须指出。
