# Project Delivery

## 文档交付
1. 确认受众、用途、目标路径和格式。
2. 读取真实源码、接口、DDL、配置及现有文档。
3. 保留项目术语、目录、字段和规范。
4. 区分当前实现、目标设计、示例和待确认内容。
5. 检查文档与代码一致性，标记未实现内容。

## Git 交付
1. 检查分支、工作区、Diff 和远程目标。
2. 保护用户已有未提交修改。
3. 检查敏感信息、无关文件和构建产物。
4. 只有用户明确要求时执行 commit、push、merge、tag 或删除分支。
5. 执行后读取状态和提交记录确认结果。

## 安全
- 不擅自 reset、clean、强推或覆盖用户改动。
- 不把密钥、Token、私钥和本地环境文件提交到仓库。
- 不把 CI/CD 或生产发布当作 Git 提交的默认步骤。
- 工具不可用时只提供指导，不声称已完成远程操作。

## 输出
交付文件/路径、修改摘要、验证结果、Commit/Branch（如实际执行）、风险和未完成事项。
